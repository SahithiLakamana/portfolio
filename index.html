Privacy-Preserving Clinical NLP Extraction with Locally-Hosted LLMs

Structured symptom extraction from 101,000 clinical notes using an LLM that never leaves institutional infrastructure — every output traceable back to its source text.

LLMsPrompt EngineeringStructured OutputEvaluation Design
  • Designed a two-phase resolution architecture — a keyword match determines processing order, never what gets checked — so most of a patient's documentation never needs to reach the model, without missing symptoms phrased outside the keyword list.
  • Diagnosed a production failure by empirically fingerprinting the real inference backend (llama.cpp, not the assumed vLLM) from raw API responses, rather than trusting the documented API contract.
  • Built a fuzzy text-grounding algorithm so every extracted finding cites its exact supporting text — model-reported character offsets were rejected as unreliable by design, and low-confidence matches are dropped rather than silently guessed.
  • Caught a sample-size confound (real evaluated n as low as 15) that was making accuracy comparisons swing 30+ percentage points between supposedly identical model configurations, before it corrupted a model-selection decision.

Internal healthcare system — code not publicly available.

Constraints that shaped the design

  • Volume vs. cost: sending every line of ~101,000 notes to an LLM wasn't viable on a slow, resource-constrained model server.
  • Privacy: all inference had to run on internally-hosted infrastructure — no data could leave institutional boundaries.
  • Trust: downstream clinical review meant every finding needed a verifiable textual basis, not just a label.

Architecture

For each patient, lines with an obvious keyword match are checked first (Phase A). Only if a target symptom is still unresolved does the pipeline fall back to that patient's remaining lines (Phase B) — if Phase A resolves everything, Phase B is skipped entirely. Requests are batched and schema-constrained via grammar-constrained decoding (symptom, status, supporting text, confidence), eliminating free-text parsing failures. Once a symptom is resolved for a patient, it's dropped from further queries for that patient.

Key technical challenges

  • Backend misdiagnosis: the pipeline was built assuming a vLLM-style backend using guided_json. Production testing showed malformed responses. Targeted, isolated API calls — reading model-file-format details in raw responses — revealed the real backend was llama.cpp with a different structured-output convention (json_schema). Fixing the parameter resolved it immediately.
  • Truncation vs. token budget: longer response limits hurt accuracy and caused timeouts; shorter limits truncated mid-JSON. Solved by bounding only the one open-ended field (the supporting quote) via the grammar itself, verified empirically to be honored by the server.
  • Reliable grounding: rather than trusting LLM-reported character offsets (unreliable and undetectably wrong when they fail), the model quotes text verbatim and a coverage-based fuzzy-matching algorithm locates the best-aligned span in the source line — below a confidence threshold, the match is rejected outright.
  • Iterative prompt refinement: structured review of outputs against labeled cases surfaced specific, fixable error patterns — clinical-name substitution, evidence misattribution between related symptoms, inferring symptoms from a diagnosis mention alone, and confusing chronic/baseline conditions with acute findings.

Evaluation methodology

Built a standalone evaluation framework independent of the extraction pipeline: expanded ground truth to a full (patient × symptom) grid so "never mentioned" cases are scored, excluded infrastructure failures (timeouts, malformed responses) from accuracy metrics entirely rather than counting them as wrong, and — after catching evaluated samples silently dropping to under 15 cases due to server-load variance — enforced a fixed evaluation grid before trusting any metric comparison.

Model comparison

Benchmarked a large general-purpose open-weight model against a smaller domain-tuned medical model: the general model ran ~3x faster and more consistently, while the medical model showed meaningfully better accuracy and text-grounding quality. This is informing a proposed hybrid strategy — fast model for initial screening, accurate model reserved for verification on the smaller candidate set.

Reliability engineering

Per-request retries with backoff, isolation of malformed responses so a single bad output never invalidates its batch, structured error categorization (timeout / malformed / connection failure) surfaced for auditability, and file-level resumability so a long-running job over the full dataset can be safely restarted.

Tech stack

Python · locally-hosted LLM (llama.cpp) · pandas · pydantic · grammar-constrained decoding

Reddit-Based Early-Warning System for Emerging Drug Trends

An NLP + statistics pipeline that detects new psychoactive substances in social media discussion 1–2 years before official surveillance data catches up.

Problem

New psychoactive substances (NPS) typically take 1–2 years to reach official detection through clinical reports, forensic labs, or law enforcement seizures — a delay that limits harm-reduction and policy response. Reddit hosts early, informal discussion of emerging drugs months or years ahead of official channels, but manually monitoring thousands of posts across tens of thousands of subreddits isn't feasible.

Production infrastructure

A 24/7 Python pipeline ingests Reddit (primary, ~1M posts/day) and Twitter (secondary) via authenticated, rate-limit-aware API clients, runs classification + topic modeling (LDA) + sentiment analysis, and aggregates into MongoDB — with raw post text discarded after feature extraction for a 96%+ storage reduction while retaining full analytical value. Building & Externally Validating an ICU Mortality Risk Model

Trained gradient-boosted models on local EHR data, benchmarked them against a published mortality-risk model, then validated the result in live clinical deployment.

Clinical MLGradient BoostingModel ValidationCalibration
  • Reconstructed and externally validated the published SafeNET model on 7,773 patients (8,253 encounters) at an independent health system — AUC 0.87 — then trained CatBoost/LightGBM/XGBoost models on local data that outperformed it (AUC 0.92, F1 0.77).
  • Ran a full retrospective validation followed by a prospective clinical deployment; confirmed no meaningful performance drift over 2–3 months of live use.
  • Addressed 91–99% missingness in key predictors through a clinician-education intervention that cut missingness by 50–80% without any system changes.
  • Published in Critical Care Explorations; presented at AMIA 2025.
GitHub — Repository
View full case study

Context

Interhospital transfer (IHT) affects 1.6M+ US adults annually. SafeNET, a mortality-risk model developed at a different institution, had never been validated outside its home system — and pre-transfer clinical data is notoriously fragmented across health systems, raising the question of whether an externally developed model could perform reliably with real-world data gaps.

Approach

  • Data harmonization: mapped 14 SafeNET predictors (vitals, labs, comorbidities, functional status) across incompatible local EHR schemas; manually verified outcomes due to data fragmentation.
  • Class imbalance: tested random under-sampling vs. algorithm-level class weighting for the ~1:27 mortality-to-survival ratio — class weighting won.
  • Missing data: combined native tree-model null handling, dynamic per-encounter feature availability, and a reduced 10-core-variable feature set selected for minimal missingness.
  • Validation: stratified 70/30 train-test split, 5-fold cross-validation optimizing F1, held-out test evaluation, then live prospective monitoring post-deployment.
